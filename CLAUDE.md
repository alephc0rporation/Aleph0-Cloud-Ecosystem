# Aleph0 Cloud Ecosystem

## Overview

Aleph0 is our own cloud platform built on OpenStack. The MVP will offer VMs, block and S3
storage, virtual networks and L4 load balancers, plus scheduled backups, basic per-VM metrics and
quotas per organization. Only the app skeleton exists today: login, `/healthz` and `/v1/me`.

- **Two ways in:** a React web portal and a public REST API. The API is a product in its own
  right: customers call it directly, not only through the portal.
- **OpenStack stays hidden:** customers never talk to OpenStack; the Go backend translates their
  requests into OpenStack calls (see Tenancy below).
- **Spec-first:** `api/openapi.yaml` is the contract. Go server code and the TypeScript client
  are generated from it, so backend and frontend cannot drift apart.
- **Login:** Keycloak (OIDC). The portal signs users in; the API accepts only Keycloak access
  tokens issued for it.

Full plan: [docs/architecture.md](docs/architecture.md). Design decisions:
[docs/superpowers/specs/](docs/superpowers/specs/). Where a spec and the code disagree, the code
wins (e.g. the skeleton spec says Radix; the code uses Base UI).

## 2. Architecture and tools

- **Local flow:** browser → Vite (:5173) → `/v1` proxied to the API (:8080) → token checked with
  Keycloak's signing keys (fetched from :8081 and cached, no call per request) → PostgreSQL
  (:5432, database `api`). Dev runs on Linux (WSL2 on Windows).
- **Production:** GCP (EU) runs the frontend (Cloud Storage + CDN), the API and job worker
  (Cloud Run), Keycloak and Cloud SQL. A site-to-site VPN connects to 3 own nodes running
  OpenStack (Kolla-Ansible) and Ceph (cephadm).
- **OpenStack services:** Nova/KVM (VMs), Cinder on Ceph RBD + Ceph RGW (volumes, S3), Neutron
  with OVN (networks, routers, floating IPs), Octavia with OVN provider (L4 load balancers).
- **Tenancy:** organization = Keycloak group = one OpenStack project. Keycloak authenticates the
  platform only (no Keystone federation). OpenStack is the source of truth for resources; our
  database never mirrors VMs or volumes. OpenStack APIs stay private; the Go backend is their
  only client, as a Keystone service user with the `member` role and a token scoped to the
  organization's project on every request.
- **Backend:** Go 1.27, standard library first (`net/http`, `log/slog`), no web framework.
  oapi-codegen (strict server), go-oidc, kin-openapi + nethttp-middleware, pgx/v5.
- **Frontend:** Node 24, React 19, Vite, TypeScript (strict), TanStack Router + Query, orval
  (Query hooks + Zod), Tailwind CSS v4, shadcn/ui on **Base UI, not Radix**, lucide-react,
  oidc-client-ts + react-oidc-context.
- **Local services:** Docker Compose with PostgreSQL 18 and Keycloak 26.
- **Planned, use these when the need comes (don't pick alternatives):** goose migrations + sqlc
  queries (`go tool` entries, `api migrate`), Gophercloud v2 (`internal/openstack/`), job worker
  (`api worker`, `internal/jobs/`), Stripe (`internal/billing/`), Zustand only once there is
  shared client-side UI state, Terraform (libvirt) for dev VMs. Expected for forms and tables:
  react-hook-form + Zod and TanStack Table.
- **Planned tables:** `organizations`, `memberships` (role admin/member), `jobs`,
  `resource_events` (audit trail of create/resize/delete).

## 3. Hard rules (never break)

- **IMPORTANT: Never add yourself as author or co-author.** No `Co-Authored-By` trailer, no
  "Generated with Claude Code" line, no session link, in commits or pull requests.
- **IMPORTANT: Never read, print or edit secret files:** `.env` and its variants, private keys,
  credential files and keyrings. To learn variable names, read `.env.example`.

## 4. Working in this repo

### Commands

Run from the repo root; the Makefile loads `.env`. First run: the developer copies
`.env.example` to `.env`.

| Command | Does |
|---|---|
| `make up` | Start PostgreSQL and Keycloak, wait until healthy |
| `make dev` | API and web; log in as `dev@aleph0.local` / `dev` |
| `make test` | Go vet + tests, ESLint, TypeScript check, Vitest |
| `make generate` | Regenerate Go and TypeScript code from `api/openapi.yaml` |
| `make down` | Stop the containers |
| `make reset` | Delete all local data and start again (destructive) |

Code generators are pinned per project (`go tool oapi-codegen`, `orval` as a devDependency).
Never install them globally.

### Changing the API

1. Edit `api/openapi.yaml`. Put every input constraint (`required`, `minLength`, `pattern`,
   `maximum`, enums) in the spec: middleware validates requests before handlers run.
2. Run `make generate`. Generated code is committed; never edit it by hand.
3. Implement the new `oapi.StrictServerInterface` method in `api/internal/handlers`.
4. Use the generated hook from `web/src/api/gen/api.ts` in the frontend.
5. Add tests on both sides and run `make test`.

Errors use `#/components/schemas/Problem` (`application/problem+json`); `401`s reuse
`#/components/responses/Unauthorized`.

### Backend

- Everything under `/v1/` requires a token automatically (`requireAuth` in `server.Handler`).
  Put an endpoint outside `/v1/` only on purpose, like `/healthz`, and give it `security: []` in
  the spec. Read the caller with `auth.FromContext(ctx)`.
- Tokens: RS256, `iss` = `OIDC_ISSUER`, `aud` contains `OIDC_AUDIENCE` (`api`); ID tokens are
  rejected. Keys load lazily, so the API starts without Keycloak.
- Every error response goes through `problem.Write`. `detail` is public: never put internal
  errors, SQL or OpenStack messages in it. Handlers return a typed response for expected
  outcomes and an `error` for unexpected ones (logged, empty 500).
- Log with `slog.InfoContext(ctx, ...)` and friends so `request_id` is attached.
- Middleware order (outermost first): request ID → access log → panic recovery → 1 MiB body
  limit → mux → auth (`/v1/`) → spec validation → handler.
- New env variables go in `internal/config` (through the injected `getenv`) and `.env.example`.
  The API never reads `.env` itself. Values in `.env.example` have no quotes and no `$` (Make
  reads the file).
- Inject dependencies as small functions or interfaces (e.g. `Handlers.Ping`); give outbound
  calls a context deadline.
- Tests: `go test` + `httptest`, no Docker or network. Black-box `package x_test` unless
  testing unexported code.

### Frontend

- Fetch API data only through the generated hooks. Errors arrive as `ApiError`. Queries retry
  network errors and 5xx, never 4xx.
- Protected routes call `context.auth.signinRedirect()` in `beforeLoad`. The fetcher redirects on
  a 401 only without a session or with an expired one; a 401 for a fresh token throws instead,
  because a redirect would loop through Keycloak.
- Add UI components with `npx shadcn add <name>` from `web/`. Use `import type` for types and
  the `@/` alias for imports.
- Only `VITE_*` variables reach the browser. The dev server is pinned to :5173 (Keycloak
  redirect URI); `/v1` is proxied, there is no CORS by design.
- Tests: Vitest; mock `@/auth/oidc` and stub `fetch`.

### Local environment

- Changes to `realm-dev.json` or `init.sql` apply only after `make reset`.
- 401 on every call after login: the token's `iss` is not `http://localhost:8081/realms/aleph0`
  or its `aud` lacks `api`; the API logs `access token rejected` with the reason.
- Containers publish on `127.0.0.1` only. Files use LF line endings.

### Security

- Secrets live in `.env` (never committed) or Secret Manager. Values in `.env.example`,
  `init.sql` and `realm-dev.json` are for local development only.
- Every new endpoint needs an auth decision and, once organizations exist, a check that the
  caller's organization owns the resource.

### Git

- Conventional Commits, lowercase imperative subject: `feat(api): ...`, `fix(web): ...`,
  `docs: ...`, `chore: ...`. Scopes: `api`, `web`.
- Branches start with `feat/`; merge into `main` through a pull request.

### Definition of done

- `make test` passes.
- `make generate` leaves `git status` clean.
- No hand edits in `api/internal/oapi/`, `web/src/api/gen/` or `web/src/routeTree.gen.ts`.
