# App skeleton — design

Issue: #3 (part of #1, blocks #4)
Date: 2026-10-27

## Goal

The local app stack working end to end, without OpenStack: a user logs in from the browser through Keycloak, the Go API validates the token, and the API can reach PostgreSQL. Every later feature (#4 and beyond) adds endpoints and pages on top of this without restructuring it.

## Decisions

| Topic | Decision | Why |
|---|---|---|
| Dev environment | WSL2 (Ubuntu 26.04), repo in the WSL filesystem (`~/projects/`), not `/mnt/c` | The infra work (#2) needs Linux anyway; the Makefile, CI and production are Linux; `/mnt/c` is slow |
| API contract | Spec-first: `api/openapi.yaml` is the source of truth | The API is a product used by customers, not only by the portal; one contract feeds Go, TypeScript and customer docs |
| Go HTTP layer | `net/http` (Go 1.22+ routing) + code generated by `oapi-codegen` (`std-http-server` + `strict-server`) | No framework; typed handlers; standard middleware works |
| Frontend API client | `orval` generates TanStack Query hooks and Zod schemas from the same spec | Go and TypeScript can never drift apart |
| UI library | shadcn/ui (Tailwind CSS + Radix), components copied into the repo | Full control of the look; pairs with TanStack Table and react-hook-form + Zod |
| Migrations | goose and `api migrate` are **not** part of #3 | No tables yet, and `//go:embed` fails on an empty folder; goose arrives with the first table, together with sqlc |
| CORS | None | Vite proxies `/v1` in dev; in production web and API sit behind the same domain (decided with the GCP deployment) |

## Dev environment

Installed in WSL:

- Go 1.27 (`linux/amd64`)
- Node 24 LTS (npm ships with it)
- `make`
- Docker Desktop with WSL integration enabled for `Ubuntu-26.04`

Code generators are pinned per project, with no global installs:

- `oapi-codegen` is declared as a `tool` in `api/go.mod` and run with `go tool oapi-codegen`
- `orval` is a `devDependency` in `web/package.json`

Generated code (Go and TypeScript) is committed, so `go build` and `npm run dev` work without running the generators first.

## Local services (`docker-compose.yml`)

Image tags are pinned to exact versions when implemented (PostgreSQL 18, Keycloak 26).

**PostgreSQL**

- One instance, two databases, each with its own user and no access to the other:
  - `api`: application data
  - `keycloak`: Keycloak data
- Created by `deploy/postgres/init.sql` on first start (`/docker-entrypoint-initdb.d/`)
- Data in a named volume
- Healthcheck with `pg_isready`

**Keycloak**

- `start-dev --import-realm`, realm file mounted from `deploy/keycloak/`
- Stores its data in the `keycloak` PostgreSQL database (same as production), starts after PostgreSQL is healthy
- Bootstrap admin credentials come from `.env`

**Ports** (with `networkingMode=mirrored`, all reachable from the Windows browser on `localhost`). Containers publish on `127.0.0.1` only, so the dev credentials never reach the local network.

| Service | Port |
|---|---|
| web (Vite) | 5173 |
| api | 8080 |
| Keycloak | 8081 |
| PostgreSQL | 5432 |

**Realm `aleph0`** (`deploy/keycloak/realm-dev.json`)

- Client `web`: public, standard flow only, PKCE `S256` required
  - redirect URIs and post-logout redirect URIs: `http://localhost:5173/*`
  - web origins: `http://localhost:5173`
  - an audience mapper adds `api` to the access token's `aud`
- Client `api`: all flows disabled; it exists only as the token audience
- Test user: `dev@aleph0.local` / `dev`, email verified, name "Dev User" (dev only)
- User registration disabled

**Known behaviour:** `--import-realm` skips a realm that already exists. After editing `realm-dev.json`, run `make reset`.

**Issuer:** the API runs in WSL, not in a container, so the browser and the API both reach Keycloak at `http://localhost:8081/realms/aleph0`. The `iss` claim matches what the API expects.

## Backend

### Contract (`api/openapi.yaml`, OpenAPI 3.0)

| Endpoint | Auth | Responses |
|---|---|---|
| `GET /healthz` | none | `200 {"status":"ok"}`; `503 {"status":"unavailable"}` when the DB ping fails or takes longer than 2 s |
| `GET /v1/me` | Bearer JWT | `200 {"id","email","name"}` taken from the token's `sub`, `email`, `name` claims; `401` problem |

Errors use RFC 9457 Problem Details (`application/problem+json`) with `type`, `title`, `status`, `detail`. This shape is part of the public contract from day one. A `401` also sets `WWW-Authenticate: Bearer`.

### Generated code

`oapi-codegen` generates models, the `std-http-server` router and the `strict-server` interface into `internal/oapi`. Handlers in `internal/handlers` implement `StrictServerInterface`, so they receive typed requests and return typed responses.

### Authentication (`internal/auth`)

- Reads `Authorization: Bearer <token>`
- Verifies with `coreos/go-oidc/v3`:
  - signature (RS256) against Keycloak's JWKS (`<issuer>/protocol/openid-connect/certs`)
  - `iss` equals `OIDC_ISSUER`
  - `aud` contains `OIDC_AUDIENCE` (`api`)
  - `exp` not passed
- The key set is fetched lazily on the first token, and again when a token carries an unknown key ID. The API starts even when Keycloak is down.
- On success, `sub`, `email` and `name` go into the request context. On failure: `401` problem.
- The middleware wraps the whole `/v1/` subtree. Any new `/v1` endpoint requires a token unless it is deliberately mounted outside that subtree.

### Server (`internal/server`)

Middleware order: request ID → access log → panic recovery → (auth, `/v1/` only) → handler.

- Request ID: generated per request, returned as `X-Request-Id`, included in every log line
- Logs: `log/slog`, JSON to stdout; access log fields `request_id`, `method`, `path`, `status`, `duration_ms`
- Panic recovery: logs the panic, returns a `500` problem
- `http.Server` timeouts: `ReadHeaderTimeout` 5 s, `ReadTimeout` 15 s, `WriteTimeout` 30 s, `IdleTimeout` 60 s
- Graceful shutdown on SIGINT / SIGTERM, 10 s grace period
- Database: `pgx/v5` `pgxpool`; the pool connects lazily, so the API starts while the DB is down and `/healthz` reports it

### Config (`internal/config`)

| Variable | Required | Default |
|---|---|---|
| `HTTP_ADDR` | no | `:8080` |
| `DATABASE_URL` | yes | |
| `OIDC_ISSUER` | yes | |
| `OIDC_AUDIENCE` | yes | |

Missing required variables stop the process at startup with one message listing all of them. The Makefile loads `.env`; the API does not read `.env` itself.

### Commands

`cmd/api/main.go` dispatches on `os.Args[1]`. #3 ships `serve` only; `migrate` and `worker` arrive with their issues. An unknown or missing command prints usage and exits with status 2.

## Frontend

- Vite + React + TypeScript (`strict`), npm
- **Routing:** TanStack Router with file-based routes (`@tanstack/router-plugin`)
- **Auth:** `oidc-client-ts` + `react-oidc-context`
  - Authorization Code + PKCE against client `web`
  - tokens in `sessionStorage` (the library default), renewed automatically with the refresh token
  - after the redirect back, `onSigninCallback` removes the `code` and `state` query parameters from the URL
  - protected routes call `signinRedirect()` from `beforeLoad` when there is no authenticated user
  - logout ends the Keycloak session too (`signoutRedirect`)
- **API client:** `orval` reads `../api/openapi.yaml` and writes TanStack Query hooks and Zod schemas into `src/api/gen/`
- **Fetch wrapper** (`src/api/fetcher.ts`, the orval mutator):
  - adds `Authorization: Bearer <access token>`
  - on `401` without a session or with an expired one, starts `signinRedirect()`
  - on a `401` for a fresh token, throws instead: Keycloak still has a session, so a redirect would loop
  - on any other non-2xx, throws an error carrying the problem details (type generated from the spec)
- **Retries:** TanStack Query retries network errors and 5xx only, never 4xx
- **Dev proxy:** Vite forwards `/v1/*` to `http://localhost:8080`
- **Config:** Vite reads the root `.env` (`envDir: '..'`); only `VITE_OIDC_AUTHORITY` and `VITE_OIDC_CLIENT_ID` reach the browser
- **UI:** shadcn/ui on Tailwind CSS; only `button` and `card` are added now
- **Page:** `/` is protected and shows the name and email from `/v1/me`, a logout button, and loading and error states

Not in #3: Zustand (no client-side UI state yet; auth state lives in `react-oidc-context`, server state in TanStack Query), forms (#4).

## Dev commands (`Makefile`)

The Makefile loads `.env` when present and exports its variables.

| Command | Does |
|---|---|
| `make up` | `docker compose up -d --wait` |
| `make dev` | runs `go run ./cmd/api serve` and `npm run dev` in parallel; Ctrl+C stops both |
| `make generate` | runs `oapi-codegen` and `orval` |
| `make test` | `go vet ./...`, `go test ./...`, ESLint, `tsc --noEmit`, Vitest |
| `make down` | `docker compose down` |
| `make reset` | `docker compose down -v`, then `make up` (fresh DB, realm re-imported) |

`web/node_modules/.package-lock.json` (written by npm only after a successful install) is a Make target that depends on `web/package-lock.json` and runs `npm ci`, so dependencies install on first use, again when the lock file changes, and again after a failed install.

## Testing

**Go** (`go test` + `httptest`, no external services):

- Auth middleware, with tokens signed by an RSA key generated in the test and a static key set:
  - valid token → handler runs, claims in context
  - missing header, malformed header, wrong `aud`, wrong `iss`, expired, wrong signature → `401` problem with `WWW-Authenticate`
- `/healthz` with a fake ping function: success → `200`, error → `503`
- `/v1/me` returns the claims from the context
- Config: missing required variables → error naming each of them

**Web** (Vitest):

- Fetch wrapper: attaches the bearer token; a `401` without a session or with an expired one triggers `signinRedirect`; a `401` for a fresh token does not

## Documentation

- `README.md`: prerequisites (`.wslconfig`, Docker WSL integration, Go and Node install), first run, commands, troubleshooting (realm not re-imported, ports in use)
- `docs/architecture.md`: the original plan translated to English and updated with the decisions made so far (WSL, smaller dev VMs, spec-first API, shadcn/ui)

## Acceptance criteria

From WSL, on a clean checkout:

1. `cp .env.example .env`, `make up`, `make dev` start everything
2. Opening `http://localhost:5173` redirects to Keycloak; logging in as `dev@aleph0.local` / `dev` returns to the app
3. The page shows the name and email returned by `/v1/me`
4. `curl localhost:8080/v1/me` without a token returns `401` with `application/problem+json`
5. `/healthz` returns `200` with the stack up and `503` after `docker compose stop postgres`
6. Logout returns to Keycloak's login page; reloading the app asks for login again
7. `make test` passes
8. Running `make generate` on a clean checkout leaves `git status` clean

## Out of scope

- OpenStack client and any `/v1/servers` endpoint (#4)
- Request validation against the spec (arrives with the first request body, in #4)
- DB schema, sqlc, goose, `api migrate`
- Job worker
- Hot reload for the Go API
- CI (separate issue: run `make test` and check generated code is up to date)
- GCP deployment, production CORS / domain layout
